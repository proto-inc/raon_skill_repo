# raon-codebase-to-docs

이미 코드가 있는 프로젝트를 읽고, [raon-spec-to-docs](../raon-spec-to-docs/SKILL.md)와 **같은 `docs/` 구조**로 사양 문서를 만든다. 질문으로 처음부터 기획하는 스킬이 아니다. 코드와 기존 문서에서 확인되는 것만 적는다.

이 스킬은 특정 AI 도구에 묶이지 않는다. Claude Code, Codex, Cursor에서 쓴다.

## 쓰지 않는 경우

`docs/01-planning/`이 있고 `docs/README.md`에 결정 ID 규칙(F-, D-, DS-, TD- …)이 있으면 이 프로젝트는 이미 raon 사양 문서다.

- 폴더를 `legacy/`로 옮기지 않는다.
- 문서를 새로 쓰지 않는다.
- [사양 문서 훅](#사양-문서-훅)이 없으면 설치하고, 이미 있으면 끝낸다.
- 사양을 바꾸려면 `raon-spec-to-docs`의 규칙대로 해당 문서를 고친다.

## 핵심 원칙

1. **코드가 사실의 기준이다.** 문서에 적힌 내용과 코드가 다르면 코드를 따른다. 문서에만 있고 코드에 없는 기능은 완료로 쓰지 않는다.
2. **확인한 것과 추정한 것을 구분한다.** 파일 경로를 댈 수 있는 문장만 사실로 쓴다. 코드만으로 모르는 의도·비용·법적 판단은 '결정 대기'에 둔다. 지어내지 않는다.
3. **없는 영역은 파일을 만들지 않는다.** 예를 들어 외부 데이터 갱신이 없으면 `data-sync.md`를 만들지 않는다.
4. **기존 문서는 지우기 전에 `legacy/`로 옮긴다.**
5. **사양이 바뀌면 문서를 먼저 고친다.** 마지막에 훅을 설치한다.

## 진행

한 번에 문서를 쓰고, 끝나면 아래 [완료 보고](#완료-보고)로 알린다. 사용자에게 "다음"을 묻지 않는다. 코드로 정할 수 없는 항목은 질문하지 않고 '결정 대기'에 둔다.

### 1. 코드 읽기

구현을 추적한다. 진입점, 화면·라우트, 데이터 모델, API, 인증, 설정, 테스트, 배포 설정을 찾는다. 의존성 목록만 보고 기능을 완료로 쓰지 않는다.

비밀 키·토큰·실사용 데이터는 문서와 채팅에 옮기지 않는다.

### 2. 기존 문서를 `legacy/`로 옮기기

오늘 날짜 폴더를 쓴다. 예: `legacy/2026-10-12/`. 그 경로가 이미 있으면 `legacy/2026-10-12-2/`처럼 번호를 붙인다.

| 옮기는 대상 | 처리 |
|---|---|
| `docs/` | `legacy/<날짜>/docs/`로 이동 |
| `doc/`, `documentation/`, `design/`, `specs/`, `spec/` | 같은 상대 경로로 이동 |
| 루트의 `SPEC.md`, `DESIGN.md`, `ARCHITECTURE.md`, `PRD.md`, `REQUIREMENTS.md`, `PRODUCT.md` | `legacy/<날짜>/`로 이동 |
| 루트 `README.md` | 복사만 한다. 원본은 나중에 `docs/`를 가리키는 짧은 안내로 바꾼다 |
| `AGENTS.md`, `CLAUDE.md` | 복사해 둔 뒤, 새 규칙으로 다시 쓴다 |

소스, 테스트 코드, 락파일, 라이선스, `CHANGELOG.md`는 옮기지 않는다.

옮기기 전에 사용자에게 이동할 경로를 한 줄로 알린다. 이미 정한 동작이므로 질문지로 다시 묻지 않는다.

### 3. `docs/` 다시 쓰기

구조와 결정 ID는 `raon-spec-to-docs`와 같다.

```
docs/
├── README.md
├── 01-planning/product-requirements.md
├── 02-research/
├── 03-design/
├── 04-technical/
├── 05-implementation/
├── 06-testing/
└── 07-release/
```

각 단계 `README.md` 맨 위:

```
| 항목 | 내용 |
|---|---|
| 문서 상태 | 코드 기준 v1 (YYYY-MM-DD) |
| 작성일 | YYYY-MM-DD |
| 이전 문서 | [링크] |
| 다음 문서 | [링크] |
```

`docs/README.md` 상태 표는 **코드 기준 v1**이다. 사용자와 질문으로 확정한 문서가 아니므로 `확정 v1`이라고 쓰지 않는다.

문서 변경 규칙:

- 확정된 내용과 다르게 구현해야 하면 **문서를 먼저 고치고** 결정 ID를 남긴다.
- 사양·동작·화면·API·데이터 모델이 바뀌면 같은 작업 안에서 `docs/`를 갱신한다.
- 미정 항목은 '결정 대기'에 둔다.
- 미구현 기능은 완료로 쓰지 않는다.

단계별로 코드에서 채운다.

| 단계 | 코드에서 볼 것 | 모르면 |
|---|---|---|
| 01 기획 | 화면·라우트에 실제로 있는 기능. ID는 F-01부터 | 대상 사용자, 하지 않을 것, 비용 한도 → 결정 대기 |
| 02 조사 | 코드에 연결된 외부 서비스·SDK. 가격·약관은 확인한 출처만 | 확인하지 못하면 "(미검증)" 또는 결정 대기. 조사 파일이 필요 없으면 `README.md`만 |
| 03 화면 | 실제 화면·라우트·빈 상태·오류 상태. ID는 S-01부터 | 없는 화면은 적지 않는다. 시각 문서는 코드의 색·글자만 |
| 04 기술 | 폴더 구조, 모델, API, 인증, 권한. 결정 ID는 TD- | 코드에 없는 컬럼·엔드포인트를 만들지 않는다 |
| 05 구현 | 이미 있는 것을 완료로, 없는 것을 남은 작업으로. 마일스톤은 코드 상태에 맞춘다 | 추측한 일정을 확정하지 않는다 |
| 06 테스트 | 저장소에 있는 테스트와 그것이 잠그는 동작. ID는 T- | 테스트가 없으면 그 사실을 적고, 있어야 할 자동 테스트만 제안 |
| 07 출시 | 스토어 설정, 개인정보 문서, 배포 설정 중 파일로 있는 것 | 출시 국가·법적 판단은 결정 대기. "법률 자문 아님" |

결정 표에는 코드에서 그렇게 되어 있는 선택을 ID와 함께 적는다. 예: `TD-01 | 인증은 서버 세션. 근거: src/auth/session.ts`.

링크는 상대 경로로 두고, 없는 파일을 가리키지 않는지 확인한다.

### 4. 작업 규칙과 루트 README

`AGENTS.md`를 만든다. 이미 있으면 사양 문서 규칙을 넣되, 기존에만 있는 프로젝트 규칙은 지우지 않고 남긴다. `CLAUDE.md`는 `AGENTS.md`를 보도록 한 줄로 둔다.

넣을 문장:

- 설계 문서는 `docs/`다.
- 사양·동작·화면·API·데이터 모델이 바뀌면 코드를 더 쓰기 전에 `docs/`와 해당 단계 결정 표를 고친다.
- 미구현을 완료로 쓰지 않는다.

루트 `README.md`가 없거나, 사양 설명이 문서와 겹치면 `docs/README.md`로 안내하는 짧은 글로 바꾼다. 빌드·실행 방법처럼 코드 사용에 필요한 절은 유지한다.

### 5. 사양 문서 훅

프로젝트 루트에서 이 스킬의 스크립트를 실행한다.

```bash
python3 <이 스킬 폴더>/hooks/install.py
```

`raon-spec-to-docs/hooks/`와 같은 스크립트다. 동작은 그 스킬의 [사양 문서 훅](../raon-spec-to-docs/SKILL.md#사양-문서-훅)과 같다.

- `.cursor/hooks/spec-docs.py`
- `.cursor/hooks.json`의 `stop` 훅 (`loop_limit` 1)
- `.claude/settings.json`의 `Stop` 훅

기존 훅은 유지하고 이 항목만 추가한다. JSON이 깨져 있으면 덮어쓰지 않는다.

## 완료 보고

```
## 코드 기준으로 docs/를 다시 썼어요
**옮긴 문서**: legacy/<날짜>/ 아래 경로
**문서**: 파일별 한 줄
**코드에서 확인한 결정**: ID 2~4개
**결정 대기**: 코드만으로 모르는 것
**훅**: 설치함 / 이미 있음
```

## 지켜야 할 것

- 실제 API 키·토큰·비밀번호·개인 정보를 문서·채팅·커밋에 쓰지 않는다.
- 테스트를 통과하지 않는 기능, TODO, 빈 화면을 완료로 쓰지 않는다.
- 가격·약관·법률을 확인하지 않고 사실처럼 쓰지 않는다.
- 이미 raon 구조인 `docs/`는 `legacy/`로 옮기지 않는다.
